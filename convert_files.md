Each element of the array represents a recorded frame of gameplay and a file represents a recording.
I need you to write a python script that is going to convert these files into a different form (still json).
The converted files need to end up inside the `./public/data` directory.
The converted file needs to have this shape:
```
{
	game: string,
	game_version: string,
	character_id: number,
	character_name: string,
	move: string,
	frames: [[{
		animation_id: number,
		animation_frame: number,
		input: string,
		rotation: number,
		hurt_cylinders: { <name>: {
			center: [x: number, y: number, z: number],
			radius: number,
			half_height: number
		}},
		collision_spheres: { <name>: {
		    center: [x: number, y: number, z: number],
			radius: number,
		}},
	}]]
}
```

The following describes how to populate each value in from this schema:

# game
Copy it from the `game` value of the first frame from the original json.

# game_version
Copy it from the `game_version` value of the first frame from the original json.

# character_id
Copy it from player 1's `character_id` value of the first frame from the original json.

# character_name
Use the CSV file `./character_ids.csv` to figure out the name of the character based on the (game, character_id) combination inside the original json.
The CSV file has the following shape:
```csv
game,character_id,character_name
t8,18,Alisa
t8,11,Asuka
...
```

# move
Look at player 1 input of first 3 frames inside the recording.
If the input sequence is up, neutral, neutral the value should be `SSL`.
If the input sequence is up, neutral, up the value should be `SWL`.
If the input sequence is down, neutral, neutral the value should be `SSR`.
If the input sequence is down, neutral, down the value should be `SWR`.
Any other input sequence is considered unexpected, report a error and skip processing the file.

# frames
This is a 2D array of objects.
The first dimension of the array stores a sample of the recorded move.
The second dimension stores the frames for each sample.
And the object contains the properties stored for each frame.
There are multiple files inside `./raw` that contain the same (game, version, character, move) combination.
Each of these files is considered to be a sample recording for that move.
So all the files with same (game, version, character, move) need to get converted into one file that has multiple samples, each sample originating from 1 input file.

# animation_id
Copy it from player 1's `animation_id` value of the corresponding frame from the original json.

# animation_frame
Copy it from player 1's `animation_frame` value of the corresponding frame from the original json.

# input
Use player 1's `input` object from the original json but compress the output into a single string.
Construct that string by concatenating the following substrings:
`f` - if `forward` is true
`b` - if `back` is true
`u` - if `up` is true
`d` - if `down` is true
`l` - if `left` is true
`r` - if `right` is true
`1` - if `button_1` is true
`2` - if `button_2` is true
`3` - if `button_3` is true
`4` - if `button_4` is true
`SS` - if `special_style` is true
`R` - if `rage` is true
`H` - if `heat` is true

# rotation, hurt_cylinders, collision_spheres
These contain world coordinates.
I need these converted into a different coordinating system.
First of all, player's centroid is considered to be on the same X and Y coordinate as his `lower_torso` collision sphere center and Z equal to `floor_z`.
Each samples first frame of the recording defines how the output coordinating system will be setup for the rest of that sample.
Line that passes trough player 1's and player 2's centroids should be the X axes of the new coordinating system.
Player 1's centroid should be pointing towards -X direction while player 2's centroid towards +X direction.
Player 2's centroid needs to be the origin of the output coordinating system.
The transformation to the output coordinating system needs to preserve scale and angle between things.

# rotation
Use the value from player 1's `rotation`.
It's in radians.
The angle 0 points towards X+ and angle of pi/2 (90 deg) points towards Y+.
This is true inside the original file and needs to remain to be true in the output file.
But since the coordinating system in the output file is changed the value needs to change accordingly.

# hurt_cylinders
Use the value from player 1's `hurt_cylinders`.
The name limb_name->value dictionary style needs to remain the same, however there is no need to store the flags.
Remember to do the coordinating system transformation.

# collision_spheres
Use the value from player 1's `collision_spheres`.
The name limb_name->value dictionary style needs to remain the same.
Remember to do the coordinating system transformation.

The output files should be named using the format `<game>-<version>-<character_name>-<move_name>.json`.
Just make sure to replace any space characters inside the file name with `_` and also make the file name lowercase.
